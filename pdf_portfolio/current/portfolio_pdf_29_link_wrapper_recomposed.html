1. 기준본 보존Legacy 기준본을 유지해 회귀 위험 분리.

작업 방식

결과물 우선

배포 페이지, 플레이 영상, 개발 기록으로 결과물의 상태를 확인합니다.

구조 설계

asmdef, EventBus, Data/Core/UI 경계를 정한 뒤 구현합니다. 생성 코드는 경계 안에서만 허용합니다.

검증 분리

기능 테스트, 플레이 영상, visual QA, 성능 수치를 분리해 결과를 확인합니다.

운영 감각

Android release, Billing, App Update, localization처럼 출시 이후 필요한 작업을 문서화합니다.

팀 경계

팀 작업에서는 역할 분담, interface, namespace, 문서로 구현 책임을 명확히 둡니다.

도구화

MyTokenMate처럼 작업 중 필요한 문제를 local-only 도구로 풀어내는 생산성 실험도 병행합니다.
