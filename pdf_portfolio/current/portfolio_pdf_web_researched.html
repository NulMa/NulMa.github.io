Ghost March03

Technical Breakdown

성능 개선은 수치로 남겼습니다

9 fpsLegacy 1500 enemies
67 fpsDOTS 4096 enemies
109.5ms -> 14.92msCPU frame time

Root Cause

  • 상태, 입력, UI, 저장 책임이 전역 관리자로 집중.
  • Weapon.Update() switch 분기로 무기 확장 비용 증가.
  • 대량 오브젝트와 UI 텍스트 갱신이 같은 프레임에 집중.

Fix / Decision

  • Legacy 구조는 비교 기준으로 보존.
  • DOTS gameplay assembly와 외부 서비스 의존성 분리.
  • RenderMeshIndirect는 URP 2D 궁합 문제로 유지하지 않음.
691 -> 4instanced batches
16.93 -> 11.22msUI Toolkit GPU
17.47 -> 11.43msUI Toolkit CPU
대표 케이스스터디는 “완성한 게임”과 “그 후 구조를 다시 분석한 경험”을 함께 보여주도록 구성했습니다.

Match3LogueLike

모바일 매치3 로그라이크 구조 설계 프로젝트. 핵심은 AI 사용 자체가 아니라, AI가 구조를 지키며 일하도록 경계와 검증 장치를 먼저 설계한 점입니다.

RoleSolo / AI workflow
ToolsUnity 6, URP 2D
Boundaryasmdef, EventBus
VerifyPlayMode / EditMode

Design Rule

  • Data -> Core -> Board / Combat / Roguelike / Meta / UI / Ads 방향 고정.
  • Board와 Combat의 직접 참조 금지, EventBus만 허용.
  • Data 영역은 MonoBehaviour 없이 SO, interface, enum 중심으로 유지.

AI Guardrail

  • Data MonoBehaviour 금지, Find 금지, Update 할당 금지 hook 적용.
  • Coordinator / Worker / Verify 역할과 worktree lane 분리.
  • merge 전 기능 테스트와 실제 화면 QA를 함께 확인.
