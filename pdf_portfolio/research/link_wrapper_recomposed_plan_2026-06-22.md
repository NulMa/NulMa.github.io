# 링크 래퍼형 신규 PDF 구조 판단

작성일: 2026-06-22

## 목표

이 PDF는 웹 공개 포트폴리오(`https://nulma.github.io/`)를 대체하는 문서가 아니라, 웹에서 짧게 지나가는 구현 구조, 성능 개선, 팀 역할, 트러블슈팅 기록을 보강하는 상세 문서다. 기존 상세형을 복사해 변형하지 않고, 웹에 공개된 결과물과 내부 근거 자료를 기준으로 별도 흐름을 구성한다.

## 페이지 순서

| 페이지 | 역할 | 이유 |
|---:|---|---|
| 01 | 표지 | 이름, 직무, 대표 프로젝트 이미지, 핵심 수치만 남긴다. |
| 02 | Projects | 5개 대표 프로젝트를 출시/구조/팀/공개개발/WebGL 축으로 훑게 한다. |
| 03 | Technical Focus | 뒤 페이지의 핵심 기술 포인트를 수치와 구조 중심으로 요약한다. |
| 04 | Ghost March 출시/운영 | Google Play 출시와 Android release, 광고/IAP, localization 범위를 보여준다. |
| 05 | Ghost March 성능 재설계 | 출시 이후 구조를 다시 잡은 경험과 수치 기반 판단을 강조한다. |
| 06 | Match3LogueLike 구조 설계 | asmdef, EventBus, Data/Core/UI 경계로 AI 협업을 통제한 구조를 보여준다. |
| 07 | Match3LogueLike 검증 루프 | 테스트 evidence와 visual QA로 변경 결과를 확인한 방식을 보여준다. |
| 08 | IronSarcophagus 구현 범위 | 팀 프로젝트에서 본인 역할과 시스템 경계를 분리한다. |
| 09 | LostCone 공개 개발과 입력 이슈 | 공개 개발과 Input System 문제 해결을 문제-시도-원인-해결 흐름으로 압축한다. |
| 10 | Cubika WebGL 배포 | 작은 프로젝트를 빠르게 완성하고 후속 개선한 경험으로 배치한다. |
| 11 | Work Style | 반복되는 개발 원칙을 카드 형태로 정리한다. |
| 12 | Links / Contact | 모든 공개 링크와 연락처를 한 페이지에 모은다. |

## 적용 원칙

- private repo는 주력 링크에서 제외하고 공개 접근 가능한 링크를 우선한다.
- 프로젝트 나열보다 "웹에서 보이는 결과 -> 상세 구현 기록 -> 보강 포인트" 순서로 읽히게 한다.
- Ghost March는 출시와 성능 재설계를 분리해 대표 강점으로 둔다.
- Match3LogueLike는 AI가 만든 결과물이 아니라 AI가 구조를 지키도록 만든 개발 환경으로 설명한다.
- IronSarcophagus는 팀 결과물 전체보다 본인 담당 시스템 경계를 먼저 밝힌다.
- LostCone과 Cubika는 보조 프로젝트처럼 보이지 않도록 각각 공개 개발/빠른 배포라는 명확한 역할을 준다.
