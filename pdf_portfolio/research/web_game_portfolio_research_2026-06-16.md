# Web Research: Game Developer Portfolio Structure

## 조사 기준

- 다른 게임 개발자 포트폴리오와 게임 포트폴리오 가이드에서 반복되는 구조만 추렸습니다.
- PDF 본문에는 조사 설명을 넣지 않고, 구조/배치에만 반영했습니다.

## 반영한 패턴

1. Best work first
   - 대표작과 가장 강한 증거를 앞에 둔다.
   - 비슷한 프로젝트를 많이 나열하지 않는다.

2. Media first
   - 게임 포트폴리오는 영상, 플레이 링크, 스크린샷이 빠르게 보여야 한다.
   - PDF에서는 GIF 대신 대표 프레임과 클릭 가능한 링크를 둔다.

3. Role / team / tools upfront
   - 프로젝트 시작부에 역할, 팀 규모, 플랫폼, 도구, 담당 범위를 고정한다.
   - 팀 프로젝트는 본인 기여를 명확하게 적는다.

4. Case study format
   - Overview보다 contribution, problem, result를 우선한다.
   - 각 기여는 "무엇을 했다 / 왜 했나 / 결과가 무엇인가"로 쓴다.

5. Process and iteration
   - 완성 화면만이 아니라 의사결정, 문제 해결, 테스트, 플레이테스트를 포함한다.
   - AI 활용도 도구 사용 여부보다 작업 경계와 검증 흐름으로 설명한다.

## 참고한 공개 사례/가이드

- ScreenSkills: best work first, video/showreel, role match, contribution clarity, tools/contact/link checks.
- Champlain College: playable builds, case studies, documentation, media, tools, reflection/iteration notes.
- GameDesignSkills: curated case studies, few strong projects, role/tools/team/impact upfront, measurable results.
- David Shaver portfolio: project grid, professional/personal split, role and tech summaries.
- Bobby Brace portfolio: project overview, documentation, play/source links, my contributions, technologies.
- Dean Tate portfolio: about summary, project list, contributions, studio/platform/reception/tools/team size.
- Reddit / Stack Overflow discussion: screenshots/videos/source, lessons learned, easy access, quality over quantity.
